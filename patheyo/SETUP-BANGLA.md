# Patheyo — অ্যাপ ↔ ওয়েবসাইট ↔ অ্যাডমিন প্যানেল সংযোগ (একবারের সেটআপ)

এই সেটআপ শেষ হলে যা পাবেন:
1. ওয়েবসাইটের **“অ্যাপ আপডেট করুন”** বাটনে চাপলে ফোনে ইনস্টল থাকা Patheyo অ্যাপ নিজেই খুলে আপডেট যাচাই করবে (অ্যাপ না থাকলে APK ডাউনলোড হবে)।
2. **অ্যাডমিন প্যানেল** (`/patheyo/admin/`) থেকে দেখবেন — এখন কতজন অ্যাপ ব্যবহার করছে, কে কোন ভার্সনে, নতুন ইনস্টল, দৈনিক চার্ট, ফোনের মডেল।
3. অ্যাডমিন প্যানেল থেকে **নোটিফিকেশন পাঠাতে** পারবেন (সবাইকে, বা শুধু নির্দিষ্ট ভার্সনের ইউজারকে)।
4. GitHub-এ **নতুন Release দিলে** ইউজারদের ফোনে নিজে থেকে “আপডেট করুন” নোটিফিকেশন যাবে।

> সব অংশ আলাদা ও নিরাপদভাবে বসানো — কোনো ধাপ বাকি থাকলে অ্যাপ/সাইটের বাকি সব আগের মতোই চলে, কিছু ভাঙে না।

---

## ধাপ ১ — Supabase (ফ্রি) বানান ও ডাটাবেস চালু করুন
1. https://supabase.com → **New project** (নাম: patheyo, একটা ডাটাবেস পাসওয়ার্ড দিন)।
2. বাম মেনু **SQL Editor → New query** → এই প্যাকের `patheyo/supabase/schema.sql` ফাইলের **পুরো লেখা** পেস্ট করে **Run**। (আগে চালিয়ে থাকলেও আবার চালানো নিরাপদ।)
3. **Authentication → Users → Add user → Create new user**: নিজের ইমেইল ও শক্ত পাসওয়ার্ড দিন (Auto Confirm User টিক দিন)। তৈরি হলে ইউজারের **UID** কপি করুন।
4. **Authentication → Sign In / Providers → Email**: “Allow new users to sign up” **বন্ধ** করুন (যাতে অন্য কেউ অ্যাকাউন্ট না বানাতে পারে)।
5. SQL Editor-এ চালান (UID বসিয়ে):
   ```sql
   insert into admins(user_id) values('এখানে-আপনার-UID');
   ```
6. **Project Settings → API**: **Project URL** আর **anon public** key কপি করুন। (`service_role` key কোথাও দেবেন না!)

## ধাপ ২ — ওয়েবসাইটে সংযোগ
`patheyo/config.js` খুলে দুটি লাইন পূরণ করুন:
```js
SUPABASE_URL:"https://xxxxxxxx.supabase.co",
SUPABASE_ANON_KEY:"eyJ...আপনার anon key...",
```
(`APP_PACKAGE` আগেই `com.gunjoron.patheyo` বসানো আছে — এটাই “অ্যাপ আপডেট করুন” বাটনকে অ্যাপের সাথে জোড়ে।)

## ধাপ ৩ — অ্যাপে সংযোগ (v49)
অ্যান্ড্রয়েড স্টুডিওতে `app/src/main/java/com/gunjoron/patheyo/stats/BackendConfig.kt` খুলে **একই** URL ও anon key বসান:
```kotlin
const val SUPABASE_URL = "https://xxxxxxxx.supabase.co"
const val SUPABASE_ANON_KEY = "eyJ...আপনার anon key..."
```
তারপর অ্যাপ বিল্ড করে APK বানান। (খালি রাখলে ইউজার-গণনা বন্ধ থাকবে, বাকি সব চলবে।)

## ধাপ ৪ — নোটিফিকেশন পাঠানোর ফাংশন (Firebase + Supabase)
1. **Firebase Console** → আপনার প্রজেক্ট `hijri-tarikh` → ⚙️ **Project settings → Service accounts → Generate new private key** → একটি `.json` ফাইল নামবে। (এটা গোপন — কাউকে দেবেন না, GitHub-এ তুলবেন না।)
   - একই জায়গায় **Cloud Messaging** ট্যাবে “Firebase Cloud Messaging API (V1)” **Enabled** আছে কি দেখে নিন।
2. **Supabase → Edge Functions → Deploy a new function → Via Editor**: নাম `send-push`। এই প্যাকের `patheyo/supabase/functions/send-push/index.ts`-এর পুরো লেখা পেস্ট করে **Deploy**।
   - ফাংশনের সেটিংসে **“Verify JWT”** বন্ধ করুন (ফাংশন নিজেই অনুমতি যাচাই করে)।
3. **Edge Functions → Secrets** (বা Project Settings → Edge Functions) → দুটি সিক্রেট যোগ করুন:
   - `FCM_SERVICE_ACCOUNT` = ধাপ ৪.১-এর JSON ফাইলের **পুরো লেখা**
   - `PUSH_HOOK_SECRET` = নিজের বানানো একটা লম্বা গোপন শব্দ (যেমন ২৪+ অক্ষরের এলোমেলো লেখা) — মনে রাখুন, ধাপ ৫-এ লাগবে

## ধাপ ৫ — GitHub-এ অটো-নোটিফিকেশন
রিপো → **Settings → Secrets and variables → Actions → New repository secret** — তিনটি যোগ করুন:
- `SUPABASE_URL` (ধাপ ১.৬-এর Project URL)
- `SUPABASE_ANON_KEY` (anon public key)
- `PUSH_HOOK_SECRET` (ধাপ ৪.৩-এ যেটা দিয়েছেন হুবহু সেটা)

তারপর রিপোর **Actions** ট্যাব → **“Update releases.json” → Run workflow** একবার চালান (এতে `update.json` ও `releases.json` তৈরি হবে)।

## ধাপ ৬ — নতুন ভার্সন প্রকাশের নিয়ম (এরপর থেকে প্রতিবার)
1. অ্যাপের `build.gradle.kts`-এ `versionCode` ১ বাড়ান, `versionName` বদলান (v49-এ আছে `6` / `1.6.0`)।
2. APK বানিয়ে GitHub → **Releases → Draft a new release**: **ট্যাগ = `v` + versionName** (যেমন `v1.6.0`), APK ফাইল আপলোড, নোটে ইমোজি-সহ লাইনে নতুন ফিচার/সমস্যা সমাধান লিখুন → **Publish release**।
3. নিজে থেকে যা ঘটবে: ওয়েবসাইট নতুন ভার্সন দেখায় → অ্যাপের আপডেটার নতুন ভার্সন চেনে → সব ইউজারের ফোনে “আপডেট করুন” নোটিফিকেশন যায়, ট্যাপ করলে অ্যাপ খুলে আপডেট পপআপ আসে।

> ⚠️ **v48 → v49 একবারের কাজ:** v48 অ্যাপগুলো শুধু আগের `…/docs/update.json` ফাইল পড়ে। তাই v49 প্রকাশের সময় ওই ফাইলটা আগের নিয়মে একবার হাতে আপডেট করুন (`versionCode` = 6, `versionName` = "1.6.0", `apk_url` = নতুন APK-র লিংক)। অ্যাপ প্যাকের `UPDATE_JSON_TEMPLATE_v49.json` ফাইলটা নমুনা। v49 ইনস্টল হওয়ার পর থেকে সবকিছু অটো। (v48-এর ফোনেও “সব ইউজার”-এ পাঠানো সাধারণ নোটিফিকেশন পৌঁছায়।)

## অ্যাডমিন প্যানেল ব্যবহার
`https://patheyobygunjoron.github.io/patheyo/admin/` → ইমেইল/পাসওয়ার্ডে লগইন।
- **ড্যাশবোর্ড:** এখন অনলাইন (১৫ মিনিট), ২৪ ঘণ্টা/৭/৩০ দিনে সক্রিয়, মোট ইনস্টল, নতুন ইনস্টল, ডাউনলোড, ১৪ দিনের চার্ট, ভার্সনভিত্তিক ইউজার (কতজন পুরোনো ভার্সনে), অ্যান্ড্রয়েড ও ফোনের মডেল। প্রতি ৩০ সেকেন্ডে নিজে হালনাগাদ হয়।
- **ইউজার:** প্রতিটি ইনস্টলেশন — ভার্সন, ফোন, অ্যান্ড্রয়েড, শেষ কখন সক্রিয়। ভার্সন বা মডেল দিয়ে ফিল্টার/সার্চ।
- **নোটিফিকেশন:** “সাধারণ ঘোষণা” (শিরোনাম, বার্তা, ঐচ্ছিক লিংক ও ছবি, লাইভ প্রিভিউ) অথবা “আপডেট রিমাইন্ডার” (সর্বশেষ রিলিজের তথ্য নিজে ভরে নেয়)। সবাইকে বা শুধু একটি ভার্সনের ইউজারকে পাঠানো যায়। নিচে পাঠানোর ইতিহাস।
- **সেটআপ:** সব সংযোগ ঠিক আছে কি না এক ক্লিকে সবুজ/লাল টিকে দেখায়।

## গোপনীয়তা
অ্যাপ শুধু পাঠায়: এলোমেলো বেনামী ইনস্টল-আইডি, অ্যাপ ভার্সন, ফোনের মডেল, অ্যান্ড্রয়েড ভার্সন। নাম, নম্বর, ইমেইল, লোকেশন, কন্টাক্ট — কিছুই নয়। ডাটাবেসের টেবিলে সাধারণ মানুষ সরাসরি পড়তে/লিখতে পারে না; শুধু অ্যাডমিন (লগইনসহ) দেখতে পারে।

## সমস্যা হলে
- ড্যাশবোর্ডে “লোড হয়নি” → ধাপ ১.২ (schema.sql) Run হয়েছে কি দেখুন।
- ইউজার সংখ্যা ০ → অ্যাপ v49 ইনস্টল করে একবার খুলুন; অ্যাপের `BackendConfig.kt`-এ URL/key বসানো আছে কি দেখুন।
- নোটিফিকেশন “ব্যর্থ” → ইতিহাসের “ব্যর্থ” ট্যাগের ওপর মাউস রাখলে কারণ দেখায় (সাধারণত `FCM_SERVICE_ACCOUNT` ভুল/অনুপস্থিত)।
- সব ঠিক আছে কি না — অ্যাডমিন → **সেটআপ** ট্যাব।
